- Prerender: `vite-plugin-seo.ts` SSR-builds `src/entry-server.tsx` during the normal `vite build` and injects page markup into each route's HTML; client stays on `createRoot` (no hydration). Why: Lovable publishes with plain `vite build`, crawlers need real text + one <h1> without JS. Code that runs during render must not touch `window`/`document`/`localStorage` (use effects).
- Meta event helpers are inert compatibility exports and the global Pixel install is removed; do not re-enable them without an eligibility review. Why: this healthcare site's page and conversion context can reveal sensitive information, including after client-side navigation.
- The homepage uses HomeBookingOffer, not BookingForm; booking navigation targets /booking. Why: visitors should encounter a single consultation booking flow.
- GEO landing FAQ uses a shared selector for visible answers and FAQ schema. Why: compact consultation information must stay consistent across cities, countries, and regional pages without duplicating the preparation guide.
- City landing data contains only geography, search metadata, first-screen copy, practical FAQ and links; the Chisinau page reads this same source. Why: removed local marketing blocks must not survive as stale alternate copy.
- Prerender injects each page's Helmet JSON-LD into the static HTML head, replacing the global index.html block (blog posts keep the plugin BlogPosting). Why: crawlers without JS must see page-specific schema.
- Problem landing FAQ additions are filtered against existing topics before rendering and schema generation. Why: online-format and pricing answers should appear once and stay consistent for visitors and crawlers.
- Accordion content renders as hidden plain markup during prerender (no `window`). Why: Radix drops closed content, so FAQ answers would be missing from crawler HTML and mismatch FAQPage schema.
- Questionnaire configs mark context-dependent results with `scoreRangesMode: "contextual"`; omit inferred total-score bands from both results and PDFs. Why: symptom totals alone cannot determine a multi-condition screen such as MDQ.
- Questionnaire schema uses per-question response scales with the same fallback as the runner. Why: mixed response anchors must match the actual questionnaire.
