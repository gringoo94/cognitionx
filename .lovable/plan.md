# План: раздел тестов внутри /tools

Подраздел `/tools/tests` с 10 валидированными психологическими опросниками. У каждого теста — отдельный URL и SEO-страница, но под капотом один общий движок прохождения.

## Архитектура

Чтобы выполнить требование «отдельная страница на каждый тест» без 10x копипаста, делаем тонкий шаблон + конфиг:

```text
src/data/tests/
  index.ts            // реестр тестов, типы
  bat.ts              // BAT (выгорание)
  phq9.ts             // PHQ-9
  gad7.ts             // GAD-7
  cips.ts             // Самозванец (Clance)
  pss10.ts            // PSS-10 (стресс)
  rosenberg.ts        // Самооценка
  lay.ts              // Прокрастинация (Lay)
  fmps.ts             // Перфекционизм (Frost — сокращ.)
  das.ts              // Дисфункц. установки (короткая 17-item версия)
  atq.ts              // Авт. мысли (ATQ-30)

src/components/tests/
  TestRunner.tsx      // прохождение: прогресс, навигация, шкала Лайкерта, валидация
  TestResult.tsx      // балл, интерпретация по диапазонам, рекомендации, CTA
  TestLayout.tsx      // обёртка: hero + описание + о методике + FAQ + JSON-LD

src/pages/
  TestsHub.tsx        // /tools/tests — каталог с фильтром по теме
  TestPage.tsx        // /tools/tests/:slug — рендерит TestLayout по конфигу
```

Каждый конфиг содержит: `slug`, `title`, `seo: {title, description}`, `intro`, `about` (на чём основано, источники, валидность), `audience`, `questions[]`, `scale` (Likert 0–4 / 0–3 / yes-no), `reverseItems` (для шкал с обратными пунктами), `scoring(answers) → {score, level, interpretation, recommendation}`, `faq[]`, `relatedSlugs[]`.

## Структура страницы теста

1. **Hero** — название, для кого, время прохождения, бейдж «Бесплатно · Анонимно».
2. **TestRunner** — по 1 вопросу за раз с прогрессом, либо все на одной странице (Likert-радиокнопки). Для длинных тестов (DAS, ATQ, FMPS) — пошагово, для коротких (PHQ-9, GAD-7) — одной страницей.
3. **Результат** — балл, уровень (норма / лёгкий / умеренный / выраженный), краткая интерпретация, дисклеймер «не диагноз», CTA «Записаться на консультацию» + ссылки на смежные тесты и тематические страницы (`/depression`, `/anxiety`, `/cbt-therapy`).
4. **Блок «О тесте»** — методика, кто разработал, на чём валидирован.
5. **FAQ** — 4–6 вопросов на тест.
6. **Связанные тесты** — кросс-линковка по кластеру.

## Скоринг (подтверждённые диапазоны)

- **PHQ-9**: 0–4 минимум, 5–9 лёгкая, 10–14 умеренная, 15–19 умеренно-тяжёлая, 20–27 тяжёлая.
- **GAD-7**: 0–4 минимум, 5–9 лёгкая, 10–14 умеренная, 15–21 тяжёлая.
- **PSS-10**: 0–13 низкий, 14–26 умеренный, 27–40 высокий (с реверсом 4,5,7,8).
- **BAT-23**: по подшкалам (exhaustion, mental distance, cognitive/emotional impairment) → суммарно.
- **CIPS (20)**: ≤40 редко, 41–60 умеренно, 61–80 часто, 81–100 интенсивно.
- **Rosenberg (10)**: 15–25 норма, <15 низкая (с реверсом).
- **Lay (20)**: суммарный балл с реверсами, среднее ≈48.
- **FMPS-короткая**: по подшкалам.
- **DAS (берём DAS-17 короткую форму)**: суммарный балл, отсечки по умеренным/высоким значениям.
- **ATQ-30**: 30–150, среднее у небольных ≈48, у депрессивных ≈97.

Цифры заносим в каждый конфиг; источники указываем в блоке «О тесте».

## SEO

- `/tools/tests` — title «Психологические тесты онлайн — бесплатно и анонимно».
- Каждая страница теста — собственный SEO-кластер (title до 60, description до 160), `BreadcrumbList` (Главная → Инструменты → Тесты → …), `Quiz` или `Question`-схема + `FAQPage`.
- Добавляем все 11 URL в `public/sitemap.xml` (priority 0.8) и `seo-routes.ts`.
- В `src/pages/Tools.tsx` — карточка-вход в раздел тестов.
- Внутренние ссылки между тестами одного кластера (выгорание ↔ стресс ↔ тревога; самозванец ↔ перфекционизм ↔ прокрастинация).

## Без БД

Результаты живут только в state компонента. Никакого `localStorage`, никаких записей в Supabase. CTA на результате: «Обсудить с психологом» → `/contact`.

## Маршрутизация

В `src/App.tsx` добавляем lazy-роуты:
- `/tools/tests` → `TestsHub`
- `/tools/tests/:slug` → `TestPage` (читает конфиг из `src/data/tests/index.ts`, 404 если slug неизвестен)

## Что НЕ делаем (фиксируем рамки)

- Без БД, без сохранения, без аккаунтов.
- Без email-сборки результатов (если потом захочется — отдельной задачей).
- Без квиза-фильтра «что вас беспокоит» на входе — добавим во второй итерации.
- Без отдельной страницы «Тесты для IT» — позже как landing над теми же конфигами.

## Объём

Большой релиз: ~10 конфигов по 80–150 строк + 4 общих компонента + 2 страницы. Делаем в одну итерацию, далее правим тексты вопросов/интерпретаций по обратной связи.
